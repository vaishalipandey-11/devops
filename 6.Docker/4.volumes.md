# Docker Volumes

## What is a Docker Volume?

A **Docker Volume** is a **persistent storage** managed by Docker. It stores data **outside the container**, so the data remains even if the container is deleted.

# Why do we need Volumes?

## With a Volume

```text
           Docker Volume
                ▲
                │
        +-------+-------+
        |   Container   |
        | Application   |
        +---------------+
                │
        docker rm -f
                │
Volume Still Exists ✅
```
# What We Practiced

## 4. Commands Practiced

| Step | Command | Purpose |
|------|---------|---------|
| 1 | `docker volume create web-data` | Create a Docker volume. |
| 2 | `docker volume ls` | List all volumes. |
| 3 | `docker run -d --name web -p 8080:80 -v web-data:/usr/share/nginx/html nginx` | Run a container and mount the volume. |
| 4 | `docker inspect web` | Verify that the volume is mounted. |
| 5 | `docker exec -it web bash` | Enter the running container. |
| 6 | `cd /usr/share/nginx/html` | Navigate to the mounted directory. |
| 7 | `echo "<h1>Persistent Data</h1>" > index.html` | Create/modify a file inside the mounted volume. |
| 8 | `exit` | Exit the container. |
| 9 | `docker rm -f web` | Delete the container. |
| 10 | `docker run -d --name web -p 8080:80 -v web-data:/usr/share/nginx/html nginx` | Recreate the container using the same volume. |
| 11 | Open `http://<EC2_PUBLIC_IP>:8080` | Verify that the data is still available. |

---
### Where are Docker Volumes stored?
On Linux:

```text
/var/lib/docker/volumes/
```
# Bind Mounts
| Volume                              | Bind Mount                   |
| ----------------------------------- | ---------------------------- |
| Managed by Docker                   | Managed by Host OS           |
| Stored in `/var/lib/docker/volumes` | Stored in any host directory |
| Best for Production                 | Best for Development         |
| Docker controls data                | You control the files        |

# Docker Bind Mounts

## 1. What is a Bind Mount?

A **Bind Mount** maps a **host directory/file** directly into a container.

---

## 2. Architecture

```text
        Host Machine
/home/ubuntu/myapp
        │
        │ Bind Mount
        ▼
+---------------------------+
|      Docker Container     |
| /usr/share/nginx/html     |
+---------------------------+
```

---

# 3. Commands Practiced

| Step | Command | Purpose |
|------|---------|---------|
| 1 | `mkdir ~/myapp` | Create a directory on the host. |
| 2 | `echo "<h1>Bind Mount</h1>" > ~/myapp/index.html` | Create a webpage on the host. |
| 3 | `docker rm -f web` | Remove the previous container. |
| 4 | `docker run -d --name web -p 8080:80 -v ~/myapp:/usr/share/nginx/html nginx` | Mount the host directory into the container. |
| 5 | Open `http://<EC2_PUBLIC_IP>:8080` | Verify the webpage. |
| 6 | `echo "<h1>Hello DevOps</h1>" > ~/myapp/index.html` | Modify the file on the host. |
| 7 | Refresh the browser | Changes appear immediately without restarting the container. |

---

# 4. Command Breakdown

| Option | Meaning |
|---------|---------|
| `-d` | Run container in background. |
| `--name web` | Container name. |
| `-p 8080:80` | Map Host Port 8080 → Container Port 80. |
| `-v ~/myapp:/usr/share/nginx/html` | Mount host directory into the container. |
| `nginx` | Docker image. |

---

# 5. What We Learned

| Action | Result |
|---------|--------|
| Edit file on Host | Container sees the change instantly. |
| Restart not required | Changes are reflected immediately. |
| Delete Container | Host files remain. |
| Delete Host Files | Container also loses access to them. |

---

# Docker Volume vs Bind Mount

| Feature | Docker Volume | Bind Mount |
|---------|---------------|------------|
| Managed By | Docker | Host OS |
| Storage Location | `/var/lib/docker/volumes/` | Any host directory |
| Data Controlled By | Docker | User |
| Easy to Backup | Yes | Manual |
| Portability | High | Low |
| Production Use | ✅ Yes | ⚠️ Limited |
| Development Use | Yes | ✅ Best |
| Share Host Files | No | Yes |
| Live Code Updates | No | ✅ Yes |
| Performance | Optimized | Depends on host filesystem |
| Security | Better isolation | Host filesystem exposed |

| Question | Answer |

| What is a Bind Mount? | A Bind Mount maps a host file or directory directly into a container. |
| Why use Bind Mounts? | To edit files on the host and see changes instantly inside the container. |
