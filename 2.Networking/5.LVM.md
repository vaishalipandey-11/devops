# 1️⃣ LVM Basic Architecture

# LVM Architecture - Practical Notes

## Purpose
- Provides flexible storage management over traditional partitions.
- Allows storage to be resized and managed without reinstalling Linux.

## LVM Workflow
Disk → Physical Volume (PV) → Volume Group (VG) → Logical Volume (LV) → Filesystem → Mount Point → User Data

## Components
### 1. Physical Volume (PV)
- A disk or partition initialized for LVM.
- Command: `pvcreate`

### 2. Volume Group (VG)
- A storage pool created by combining one or more PVs.
- Command: `vgcreate`

### 3. Logical Volume (LV)
- A virtual partition created from a VG.
- Command: `lvcreate`

### 4. Filesystem
- Formats the LV to store files.
- Commands: `mkfs.ext4`, `mkfs.xfs`

### 5. Mount Point
- Makes the filesystem accessible to users.
- Commands: `mount`, `/etc/fstab`

## Typical LVM Workflow
1. Attach a new disk.
2. Create a Physical Volume (PV).
3. Create or extend a Volume Group (VG).
4. Create a Logical Volume (LV).
5. Create a filesystem.
6. Mount the filesystem.
7. Verify using `lsblk` and `df -h`.

## Common Commands
- `lsblk` – Display block devices.
- `pvs`, `vgs`, `lvs` – Show LVM summary.
- `pvdisplay`, `vgdisplay`, `lvdisplay` – Detailed LVM information.

## Enterprise Benefits
- Combine multiple disks into one storage pool.
- Online storage expansion.
- Easy storage management.
- Supports snapshots, thin provisioning, and RAID.
- Widely used in RHCSA, DevOps, AWS, Docker, and enterprise Linux servers.

# Module 2 – Physical Volumes (PV)

Learn how to prepare a disk for use with LVM by converting it into a Physical Volume (PV).

What is a Physical Volume (PV)?
A Physical Volume (PV) is a physical storage device (disk or partition) that has been initialized for use by LVM.

Before: /dev/sdb
After:
pvcreate /dev/sdb
↓
Physical Volume (PV)

The disk is now managed by LVM.

Why do we need a PV?
Linux cannot create a Volume Group (VG) directly from a raw disk.
It must first initialize the disk with LVM metadata.
That initialization creates a Physical Volume (PV).

Physical Volume Architecture
+--------------------------------+
|          Physical Disk         |
|          /dev/sdb              |
+--------------------------------+
               │
               ▼
        pvcreate /dev/sdb
               │
               ▼
+--------------------------------+
|       Physical Volume (PV)     |
|    LVM Metadata + Free Space   |
+--------------------------------+
What does pvcreate do?

When you run:
sudo pvcreate /dev/sdb

LVM:
Writes LVM metadata to the disk.
Assigns a unique UUID.
Marks the disk as an LVM Physical Volume.
Makes it available for creating or extending Volume Groups.

It does not create a filesystem.

Important Commands
Create a Physical Volume
sudo pvcreate /dev/sdb
Display all Physical Volumes (summary)
pvs

Example output:
PV         VG   Fmt  Attr PSize   PFree
/dev/sdb        lvm2 ---  10.00g  10.00g
Detailed information
pvdisplay

Shows:
PV UUID , Size , Free space,Metadata,Volume Group (if assigned),Scan for Physical Volumes,pvscan
Searches the system for all LVM Physical Volumes.

Remove a Physical Volume
sudo pvremove /dev/sdb
This removes LVM metadata from the disk.
⚠️ Never remove a PV that is still part of an active Volume Group.

# Module 3 – Volume Groups (VG)

## Definition
- A Volume Group (VG) is a storage pool created from one or more Physical Volumes.

## Purpose
- Combines multiple disks into one logical storage pool.
- Provides space for creating Logical Volumes.

## Workflow
Physical Volume(s) → Volume Group → Logical Volume

## Commands
- `vgcreate` – Create a Volume Group.
- `vgs` – Display VG summary.
- `vgdisplay` – Show detailed VG information.
- `vgscan` – Scan for Volume Groups.
- `vgrename` – Rename a Volume Group.
- `vgremove` – Remove a Volume Group.

## Best Practice
- Verify available PVs with `pvs` before creating a VG.
- Give meaningful names such as `vg_data`, `vg_logs`, or `vg_docker`.

# Module 4 – Logical Volumes (LV)

## Definition
- A Logical Volume (LV) is a virtual partition created from a Volume Group.

## Purpose
- Provides storage for filesystems and applications.
- Can be resized more easily than traditional partitions.

## Workflow
Volume Group → Logical Volume → Filesystem → Mount Point

## Commands
- `lvcreate` – Create a Logical Volume.
- `lvs` – Display LV summary.
- `lvdisplay` – Show detailed LV information.
- `lvscan` – Scan for LVs.
- `lvrename` – Rename a Logical Volume.
- `lvremove` – Remove a Logical Volume.

## Best Practice
- Use descriptive names.
- Keep free space in the VG for future growth.
- Verify VG free space before creating LVs.

| Step | Task                              | Command                                      | Expected Result              |
| ---- | --------------------------------- | -------------------------------------------- | ---------------------------- |
| 1    | Verify Volume Groups              | `vgs`                                        | Existing VG is listed        |
| 2    | Check free space                  | `vgdisplay vg_storage`                       | Shows available free space   |
| 3    | Create a 5 GB LV                  | `sudo lvcreate -L 5G -n lv_data vg_storage`  | LV created                   |
| 4    | Verify LV                         | `lvs`                                        | LV appears in summary        |
| 5    | View detailed LV info             | `lvdisplay`                                  | Shows LV details             |
| 6    | Create another LV                 | `sudo lvcreate -L 2G -n lv_logs vg_storage`  | Second LV created            |
| 7    | Verify both LVs                   | `lvs`                                        | Both LVs listed              |
| 8    | Scan for LVs                      | `sudo lvscan`                                | Detects all LVs              |
| 9    | Rename LV                         | `sudo lvrename vg_storage lv_logs lv_backup` | LV renamed                   |
| 10   | Verify rename                     | `lvs`                                        | New name displayed           |
| 11   | Remove LV *(only if not mounted)* | `sudo lvremove /dev/vg_storage/lv_backup`    | LV removed                   |
| 12   | Verify removal                    | `lvs`                                        | Removed LV no longer appears |
