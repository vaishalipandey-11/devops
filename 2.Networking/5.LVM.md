# 1️⃣ LVM Basic Architecture

# LVM Architecture - Practical Notes

## Purpose
- Provides flexible storage management over traditional partitions.
- Allows storage to be resized and managed without reinstalling Linux.

## LVM Workflow
Disk → Physical Volume (PV) → Volume Group (VG) → Logical Volume (LV) → Filesystem → Mount Point → User Data

## Components
### 1. Physical Volume (PV)
- A disk or partition initialized for LVM.
- Command: `pvcreate`

### 2. Volume Group (VG)
- A storage pool created by combining one or more PVs.
- Command: `vgcreate`

### 3. Logical Volume (LV)
- A virtual partition created from a VG.
- Command: `lvcreate`

### 4. Filesystem
- Formats the LV to store files.
- Commands: `mkfs.ext4`, `mkfs.xfs`

### 5. Mount Point
- Makes the filesystem accessible to users.
- Commands: `mount`, `/etc/fstab`

## Typical LVM Workflow
1. Attach a new disk.
2. Create a Physical Volume (PV).
3. Create or extend a Volume Group (VG).
4. Create a Logical Volume (LV).
5. Create a filesystem.
6. Mount the filesystem.
7. Verify using `lsblk` and `df -h`.

## Common Commands
- `lsblk` – Display block devices.
- `pvs`, `vgs`, `lvs` – Show LVM summary.
- `pvdisplay`, `vgdisplay`, `lvdisplay` – Detailed LVM information.

## Enterprise Benefits
- Combine multiple disks into one storage pool.
- Online storage expansion.
- Easy storage management.
- Supports snapshots, thin provisioning, and RAID.
- Widely used in RHCSA, DevOps, AWS, Docker, and enterprise Linux servers.

# Module 2 – Physical Volumes (PV)

Learn how to prepare a disk for use with LVM by converting it into a Physical Volume (PV).

What is a Physical Volume (PV)?
A Physical Volume (PV) is a physical storage device (disk or partition) that has been initialized for use by LVM.

Before: /dev/sdb
After:
pvcreate /dev/sdb
↓
Physical Volume (PV)

The disk is now managed by LVM.

Why do we need a PV?
Linux cannot create a Volume Group (VG) directly from a raw disk.
It must first initialize the disk with LVM metadata.
That initialization creates a Physical Volume (PV).

Physical Volume Architecture
+--------------------------------+
|          Physical Disk         |
|          /dev/sdb              |
+--------------------------------+
               │
               ▼
        pvcreate /dev/sdb
               │
               ▼
+--------------------------------+
|       Physical Volume (PV)     |
|    LVM Metadata + Free Space   |
+--------------------------------+
What does pvcreate do?

When you run:
sudo pvcreate /dev/sdb

LVM:
Writes LVM metadata to the disk.
Assigns a unique UUID.
Marks the disk as an LVM Physical Volume.
Makes it available for creating or extending Volume Groups.

It does not create a filesystem.

Important Commands
Create a Physical Volume
sudo pvcreate /dev/sdb
Display all Physical Volumes (summary)
pvs

Example output:
PV         VG   Fmt  Attr PSize   PFree
/dev/sdb        lvm2 ---  10.00g  10.00g
Detailed information
pvdisplay

Shows:
PV UUID , Size , Free space,Metadata,Volume Group (if assigned),Scan for Physical Volumes,pvscan
Searches the system for all LVM Physical Volumes.

Remove a Physical Volume
sudo pvremove /dev/sdb
This removes LVM metadata from the disk.
⚠️ Never remove a PV that is still part of an active Volume Group.

# Module 3 – Volume Groups (VG)

## Definition
- A Volume Group (VG) is a storage pool created from one or more Physical Volumes.

## Purpose
- Combines multiple disks into one logical storage pool.
- Provides space for creating Logical Volumes.

## Workflow
Physical Volume(s) → Volume Group → Logical Volume

## Commands
- `vgcreate` – Create a Volume Group.
- `vgs` – Display VG summary.
- `vgdisplay` – Show detailed VG information.
- `vgscan` – Scan for Volume Groups.
- `vgrename` – Rename a Volume Group.
- `vgremove` – Remove a Volume Group.

## Best Practice
- Verify available PVs with `pvs` before creating a VG.
- Give meaningful names such as `vg_data`, `vg_logs`, or `vg_docker`.

# Module 4 – Logical Volumes (LV)

## Definition
- A Logical Volume (LV) is a virtual partition created from a Volume Group.

## Purpose
- Provides storage for filesystems and applications.
- Can be resized more easily than traditional partitions.

## Workflow
Volume Group → Logical Volume → Filesystem → Mount Point

## Commands
- `lvcreate` – Create a Logical Volume.
- `lvs` – Display LV summary.
- `lvdisplay` – Show detailed LV information.
- `lvscan` – Scan for LVs.
- `lvrename` – Rename a Logical Volume.
- `lvremove` – Remove a Logical Volume.

## Best Practice
- Use descriptive names.
- Keep free space in the VG for future growth.
- Verify VG free space before creating LVs.

| Step | Task                              | Command                                      | Expected Result              |
| ---- | --------------------------------- | -------------------------------------------- | ---------------------------- |
| 1    | Verify Volume Groups              | `vgs`                                        | Existing VG is listed        |
| 2    | Check free space                  | `vgdisplay vg_storage`                       | Shows available free space   |
| 3    | Create a 5 GB LV                  | `sudo lvcreate -L 5G -n lv_data vg_storage`  | LV created                   |
| 4    | Verify LV                         | `lvs`                                        | LV appears in summary        |
| 5    | View detailed LV info             | `lvdisplay`                                  | Shows LV details             |
| 6    | Create another LV                 | `sudo lvcreate -L 2G -n lv_logs vg_storage`  | Second LV created            |
| 7    | Verify both LVs                   | `lvs`                                        | Both LVs listed              |
| 8    | Scan for LVs                      | `sudo lvscan`                                | Detects all LVs              |
| 9    | Rename LV                         | `sudo lvrename vg_storage lv_logs lv_backup` | LV renamed                   |
| 10   | Verify rename                     | `lvs`                                        | New name displayed           |
| 11   | Remove LV *(only if not mounted)* | `sudo lvremove /dev/vg_storage/lv_backup`    | LV removed                   |
| 12   | Verify removal                    | `lvs`                                        | Removed LV no longer appears |

# Module 5 – Filesystems

## Definition
- A filesystem organizes and manages data stored on a storage device.

## Purpose
- Makes a Logical Volume capable of storing files and directories.

## Common Filesystems
- XFS (Default in RHEL)
- EXT4 (Common in Ubuntu)

## Commands
- `mkfs.xfs` – Create an XFS filesystem.
- `mkfs.ext4` – Create an EXT4 filesystem.
- `lsblk -f` – Display filesystems.
- `blkid` – Display UUID and filesystem type.
- `xfs_info` – Show XFS details.
- `tune2fs -l` – Show EXT4 details.

## Best Practice
- Verify the target LV before formatting.
- Never run `mkfs` on a disk containing important data.

| Step | Task                           | Command                                     | Expected Result                     |
| ---- | ------------------------------ | ------------------------------------------- | ----------------------------------- |
| 1    | Verify available LVs           | `lvs`                                       | Existing Logical Volumes are listed |
| 2    | View block devices             | `lsblk`                                     | Identify the target LV              |
| 3    | Create an XFS filesystem       | `sudo mkfs.xfs /dev/vg_storage/lv_data`     | Filesystem created successfully     |
| 4    | Verify filesystem type         | `lsblk -f`                                  | `xfs` appears for the LV            |
| 5    | Display UUID                   | `sudo blkid`                                | UUID and filesystem type displayed  |
| 6    | View XFS information           | `sudo xfs_info /dev/vg_storage/lv_data`     | XFS metadata displayed              |
| 7    | *(Optional)* Create another LV | `sudo lvcreate -L 2G -n lv_test vg_storage` | New LV created                      |
| 8    | Format it as EXT4              | `sudo mkfs.ext4 /dev/vg_storage/lv_test`    | EXT4 filesystem created             |
| 9    | Verify                         | `lsblk -f`                                  | Shows both XFS and EXT4 filesystems |
| 10   | View EXT4 information          | `sudo tune2fs -l /dev/vg_storage/lv_test`   | EXT4 metadata displayed             |

# Module 6 – Mounting & `/etc/fstab`

## Purpose
- Mount a filesystem to make it accessible.
- Configure automatic mounting after reboot.

## Workflow
`Disk → PV → VG → LV → Filesystem → Mount Point → User`

## Mount Types
- **Temporary:** Valid until reboot (`mount`)
- **Persistent:** Configured in `/etc/fstab`

## `/etc/fstab` Format
```text
UUID=<UUID>  <Mount_Point>  <FS_Type>  defaults  0  0
```text
UUID=abcd1234  /data  xfs  defaults  0  0
```

## Common Commands
| Command | Purpose |
|---------|---------|
| `mkdir /data` | Create mount point |
| `mount DEVICE DIR` | Mount filesystem |
| `umount DIR` | Unmount filesystem |
| `df -h` | Check mounted filesystems |
| `findmnt` | Show mount hierarchy |
| `blkid` | Display UUID |
| `mount -a` | Test `/etc/fstab` |
| `lsblk -f` | Show filesystems & mount points |

## RHCSA Workflow
```bash
mkdir /data
mount /dev/vg_storage/lv_data /data
df -h
blkid
cp /etc/fstab /etc/fstab.bak
nano /etc/fstab
mount -a
```

## Best Practices
- ✅ Use **UUID** instead of `/dev/*`.
- ✅ Backup `/etc/fstab` before editing.
- ✅ Always test with `mount -a`.
- ✅ Verify using `df -h` and `findmnt`.

## Common Mistakes
- ❌ Using device names in `/etc/fstab`
- ❌ Rebooting without testing
- ❌ Mounting the wrong Logical Volume

# Module 7 – Extend Volume Group (VG)

## Objective
Increase the storage capacity of an existing Volume Group (VG) by adding a new Physical Volume (PV).

## Workflow

```
New Disk → pvcreate → vgextend → VG Size Increases
```

## Practical Steps

| Step | Command | Purpose |
|------|---------|---------|
| 1 | `lsblk` | Identify the newly attached disk |
| 2 | `pvs` | View existing Physical Volumes |
| 3 | `vgs` | View existing Volume Groups |
| 4 | `sudo pvcreate /dev/nvme2n1` | Create a Physical Volume *(Skip if already a PV)* |
| 5 | `sudo vgextend vg_storage /dev/nvme2n1` | Add the new PV to the VG |
| 6 | `vgs` | Verify VG size increased |
| 7 | `vgdisplay vg_storage` | Check total & free space |
| 8 | `pvs` | Confirm the new PV belongs to the VG |

## Verification

- `pvs` → New PV listed.
- `vgs` → VG size increased.
- `vgdisplay` → Free PE/Size increased.
- `lvs` → LV size unchanged.

## Common Errors

- Running `vgextend` before `pvcreate`.
- Using the wrong disk.
- Disk already initialized as a PV (`pvcreate` not required).
- Attaching an EBS volume in a different Availability Zone.

## Key Points

- `pvcreate` → Initializes a disk as a Physical Volume.
- `vgextend` → Adds a PV to an existing Volume Group.
- Only the **VG** grows; **LVs and filesystems remain unchanged**.

## RHCSA Tip

```
Attach Disk
     ↓
pvcreate
     ↓
vgextend
     ↓
VG Expanded ✅
```

> To use the new space, continue with:
> **Module 8 → `lvextend`** → **Module 9 → `xfs_growfs` / `resize2fs`**

# Module 8 – Extend Logical Volume (LV)

## Objective
Increase the size of an existing Logical Volume (LV) using free space available in the Volume Group (VG).

## Workflow

```
Disk → PV → VG → LV → Filesystem
             │
         lvextend
             │
Filesystem Resize (Module 9)
```

## Practical Steps

| Step | Command | Purpose |
|------|---------|---------|
| 1 | `vgs` | Check free space in VG |
| 2 | `lvs` | View current LV size |
| 3 | `lvdisplay /dev/vg_storage/lv_data` | View LV details |
| 4 | `sudo lvextend -L +3G /dev/vg_storage/lv_data` | Extend LV by 3 GB |
| 5 | `sudo lvextend -l +100%FREE /dev/vg_storage/lv_data` | *(Optional)* Use all free VG space |
| 6 | `lvs` | Verify new LV size |
| 7 | `lsblk` | Verify block device size |
| 8 | `vgs` | Confirm free VG space decreased |
| 9 | `df -h` | Filesystem size remains unchanged (until Module 9) |

## Verification

- `lvs` → LV size increased ✅
- `lsblk` → Block device size increased ✅
- `vgs` → VG free space decreased ✅
- `df -h` → No change (filesystem not resized) ✅

## Common Errors

- No free space in VG → Run `vgextend` first.
- `df -h` unchanged → Filesystem resize pending.
- Wrong LV selected → Verify using `lvs`.

## Key Points

- `vgextend` → Expands **Volume Group**
- `lvextend` → Expands **Logical Volume**
- `xfs_growfs` / `resize2fs` → Expands **Filesystem** (Module 9)

## RHCSA Tip

`lvextend` **does not** resize the filesystem. After extending an LV, always resize the filesystem using:
- **XFS:** `xfs_growfs`
- **EXT4:** `resize2fs`
