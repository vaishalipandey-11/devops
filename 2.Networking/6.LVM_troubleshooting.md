# LVM Troubleshooting – `/etc/fstab` Boot Failure (AWS EC2)

## Scenario
After adding a persistent mount in `/etc/fstab`, the EC2 instance became inaccessible via SSH after reboot.

## Symptoms
- SSH: `Connection refused`
- Ping failed
- EC2 Status Checks: ✅ Passed
- Instance entered **Emergency Mode**

## Initial Checks

```bash
ping <EC2_IP>
nc -zv <EC2_IP> 22
ssh -vvv ubuntu@<EC2_IP>
```

## Root Cause
AWS Console → **EC2 → Actions → Monitor & Troubleshoot → Get System Log**

Error:

xfs: Unknown parameter 'default'
Failed to mount /datat
Entered Emergency Mode
```

Incorrect `/etc/fstab` entry:
UUID=<UUID> /datat xfs default 0 0
```

Correct entry:
```text
UUID=<UUID> /datat xfs defaults 0 0
```

## Recovery Method 1 (EC2 Serial Console)

```bash
mount -o remount,rw /
nano /etc/fstab
mount -a
findmnt
reboot
```

## Recovery Method 2 (Rescue Instance)

1. Stop EC2
2. Detach root EBS volume
3. Attach to another EC2 instance
4. Mount the volume
5. Fix `/etc/fstab`
6. Reattach as root volume
7. Start the original instance

## Useful Commands

```bash
blkid
findmnt
df -h
mount -a
journalctl -xb
mount -o remount,rw /
```

## Best Practices

- Backup `/etc/fstab`:
  ```bash
  cp /etc/fstab /etc/fstab.bak
  ```
- Use **UUID** instead of `/dev/*`.
- Always run `mount -a` before rebooting.
- Verify with `findmnt` and `df -h`.

## Common `/etc/fstab` Errors

| Error | Result |
|-------|--------|
| Wrong UUID | Mount failure |
| Wrong FS type | Boot failure |
| `default` instead of `defaults` | Emergency Mode |
| Missing mount point | Mount failure |
| Wrong device | Filesystem not mounted |
